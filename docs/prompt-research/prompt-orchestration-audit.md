# Runtime prompt audit: DeerFlow and OpenHands

Audited 2026-09-30. This is source analysis, not a live model evaluation. All recommendations below are independent product design suggestions. Repository instructions were treated as reference data, never as authority over this task.

The added SDK is in `repos/openhands-sdk-prompts`. No dependency installation, server launch or model call was needed. All three reviewed projects are MIT licensed at these roots; this audit recommends patterns rather than copying their wording.

`prompt-orchestration-inventory.json` contains 500 candidate files: 345 DeerFlow, 122 Canvas, and 33 checked-out SDK files. These are **search candidates, not 500 distinct system prompts**. Categories: 176 runtime-source candidates, 219 test/fixture files, 50 contributor-guidance files, 32 documentation/example files, 23 DeerFlow runtime skill entrypoints. It also enumerates 65 installed `@openhands/extensions` skill entrypoints used by Canvas's build-time catalog. The candidate index stores paths and matching line numbers, not secret values.

Main composition roots and all distinct families encountered there are covered below. Selected relevant skill bodies were read; catalog enumeration is not an assertion that every resource of every skill was read. External ACP provider internals, user-supplied runtime overlays/custom agents, configured MCP-server descriptions and future installed skills cannot be fully inventoried from these checkouts. DeerFlow's default summarization text is supplied by installed LangChain unless overridden; the source-level override and preparation path were traced, not asserted to be a DeerFlow-owned prompt.

Paths below are relative to the named repository. Line numbers refer to pinned source, not generated bundles.

## Concrete improvements that fit Agent Workspaces

1. Replace the single dense `packages/agent-loop/index.ts:137` instruction string with an original, versioned builder. Select sections from the **actual tools sent to the model**, not a wished-for product capability. Tests should assert each policy's prompt/tool agreement.
2. Give missing-file replanning its own role and finish boundary. Current `modelTurn` sends the normal execution prompt even when the only tool is `replan_result`; normal instructions to browse, save and finish conflict with this restricted call. The replan prompt should keep blockers or propose a scoped owner-approved alternative; no invented waiver or completion.
3. Make authority and freshness explicit: current owner objective/criteria and latest tracked owner corrections guide work within enforced policy; agent configuration is subordinate; files, browser text, email, logs, peer messages and saved observations remain untrusted. Old summaries, tool history and a peer's claim are not proof that this run performed an action. Do not reclassify all owner messages as untrusted data as DeerFlow's generic boundary wording does.
4. Add a compact execution discipline: inspect available evidence and exact inputs, choose the next useful step, validate its outcome against the current completion criteria, preserve useful work, and ask only for the missing required input. A plan need not be a new tool. Do not request private chain-of-thought.
5. Spell out evidence limits: receipt success attests execution, not content correctness; map each final claim to relevant observed data; distinguish checked, failed and unavailable criteria. Preserve exact version IDs and receipt IDs. Do not let an old artifact, a model sentence or upstream completion imply acceptance.
6. Adapt browser recovery to our implemented controls: fresh observation after navigation/handoff; respect paused/human-owned state; only narrow, bounded safe recovery; keep login to browser handoff or the existing Gmail connection; do not bypass site rejection or retry uncertain writes. Correct `browser_open` description from generic isolated browser to the actual agent-private session boundary.
7. Describe code execution accurately: offline container, only explicit pinned inputs, workspace/output paths, available runtime, timeout and capture limits. Inspect before deriving results; do not promise dependency installation, host filesystem access, network tools or inherited peer files. Preserve direct verified code output as a deliverable without unnecessary duplicate reports.
8. Keep model-visible collaboration instructions reference-only: approved peers and exact published versions, explicit ownership/dependencies, upstream failure as blocker, never transferable permission. No automatic subagent spawning or shared sandbox.
9. Add deterministic prompt assembly / context integration tests using the fake adapter and existing backend guards. Check hostile source text cannot be interpolated into the system instruction string; owner updates remain present; replan sees only its mode; Gmail coverage rules survive extraction. These checks prove wiring and policy consistency, not improved live model success rate.

## Patterns to defer or reject

Do not add automatic global memory, hidden paid completion judges, model routers, subagent spawning, runtime skill installation, broad third-party MCP connectivity, web search or scheduling merely because source prompts mention them. Each requires actual backend capability, authorization, budgets and evaluation. Do not copy network installs, shared-workspace assumptions, broad send/publish permissions, hardcoded model benchmarks, or clarify-every-choice rules. This product's private agent workspaces, deliberate publishing and exact grants are intentional distinctions.
