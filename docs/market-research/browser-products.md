# Browser products audit: Browser Use Desktop and Skyvern

Audit date: 30 September 2026. This report is research and product recommendations, not an implementation or a claim that market fit is established.

## Scope and evidence

Read-only examination covered onboarding, capabilities exposed to agents, browser ownership, execution and recovery, reusable workflows/skills, integrations, triggers, result review, cost visibility, packaging and positioning. Actual loading/execution paths were inspected selectively; this is not an every-line security review. No competitor runtime, credential, customer account or paid model was exercised in this audit. Public issue reports are signals from a small convenience sample, not defect prevalence measurements or independently reproduced findings.

Local source snapshots:

- Browser Use Desktop: `f073b7574f7927185ebbebd87556391d5cb0cfd1`, root MIT license, at `~/Desktop/Agent Workspaces Research 2026-09-30/repos/browser-use-desktop`.
- Skyvern: `695c05698eba52716521dd2b49800e88f314b660`, root AGPL-3.0 license, at `~/Desktop/Agent Workspaces Research 2026-09-30/repos/skyvern`. Use concepts as inspiration; no source or prompt copying is proposed.
- Agent Workspaces: current local v0.6.2 source. It has no Git commit yet; local file references identify the examined baseline.

Evidence labels below distinguish **source-verified** implementation, **documented** intended behavior, **marketed** commercial claims, and **unverified** behavior that would need a live test.

### Browser Use Desktop: useful mechanics and limits

**Onboarding is a workflow, not a settings dump.** The five persisted stages and platform capability checks are visible in [`OnboardingApp.tsx:130-307`](https://github.com/browser-use/desktop/blob/f073b7574f7927185ebbebd87556391d5cb0cfd1/app/src/renderer/onboarding/OnboardingApp.tsx#L130). Copy the progression and honest readiness idea, not cookie harvesting. The prior Gmail problem in Agent Workspaces and public Desktop issue #435 both make automatic cookie import a poor default for our promised private profiles. The issue reports a Google cookie error; it does not prove Google's detection mechanism.

**Reuse has ownership.** [`harness.ts:55-170`](https://github.com/browser-use/desktop/blob/f073b7574f7927185ebbebd87556391d5cb0cfd1/app/src/main/hl/harness.ts#L55) distinguishes installed reference skills from user-authored skills. The product opportunity is a tested playbook for a task family with clear input/output requirements, a version and a demonstrated success history. A folder of prompts alone will not establish reliability.

**Convenient remote entry adds a new security boundary.** [`WhatsAppAdapter.ts:292-322`](https://github.com/browser-use/desktop/blob/f073b7574f7927185ebbebd87556391d5cb0cfd1/app/src/main/channels/WhatsAppAdapter.ts#L292) requires its trigger token for self-chat tasks. [`ChannelRouter.ts:23-155`](https://github.com/browser-use/desktop/blob/f073b7574f7927185ebbebd87556391d5cb0cfd1/app/src/main/channels/ChannelRouter.ts#L23) starts or resumes sessions and sends completion/failure/input notices. Its reply-to-task and deduplication maps here are process memory. For us, external messages must not silently become unrestricted owner commands; authenticated senders, durable deduplication, account binding and fresh approval scopes are dependencies.

**A separate browser is not a code sandbox.** [`codex/adapter.ts:139-148`](https://github.com/browser-use/desktop/blob/f073b7574f7927185ebbebd87556391d5cb0cfd1/app/src/main/hl/engines/codex/adapter.ts#L139) passes a provider approval/sandbox bypass flag. Our confirmed container execution requirement should remain authoritative. Broad host-shell capability is not a shortcut to feature parity.

**Costs and results are surfaced where work happens.** [`SessionManager.ts:371-397`](https://github.com/browser-use/desktop/blob/f073b7574f7927185ebbebd87556391d5cb0cfd1/app/src/main/sessions/SessionManager.ts#L371) records accumulated usage; [`ChatTurn.tsx:503-551`](https://github.com/browser-use/desktop/blob/f073b7574f7927185ebbebd87556391d5cb0cfd1/app/src/renderer/hub/chat/ChatTurn.tsx#L503) renders output cards. We already have usage and artifact records; the remaining opportunity is a stronger result surface and outcome-level metrics.

### Skyvern: useful mechanics and limits

**Typed outputs make work composable.** [`workflows.py:1305-1398`](https://github.com/Skyvern-AI/skyvern/blob/695c05698eba52716521dd2b49800e88f314b660/skyvern/schemas/workflows.py#L1305) defines extraction schemas, optional structured exports, login criteria, human checkpoints and file destinations. Google Sheets execution exists in [`google_sheets_blocks.py:155`](https://github.com/Skyvern-AI/skyvern/blob/695c05698eba52716521dd2b49800e88f314b660/skyvern/forge/sdk/workflow/models/google_sheets_blocks.py#L155) and [`:545`](https://github.com/Skyvern-AI/skyvern/blob/695c05698eba52716521dd2b49800e88f314b660/skyvern/forge/sdk/workflow/models/google_sheets_blocks.py#L545). These are source capabilities, not evidence that every spreadsheet/account is configured or works.

**Scheduling is implemented locally, despite stale disabled-build wording.** [`config.py:992`](https://github.com/Skyvern-AI/skyvern/blob/695c05698eba52716521dd2b49800e88f314b660/skyvern/config.py#L992) enables schedules by default. [`agent_functions.py:1038-1047`](https://github.com/Skyvern-AI/skyvern/blob/695c05698eba52716521dd2b49800e88f314b660/skyvern/forge/agent_functions.py#L1038) and [`workflow_schedule_service.py:1-135`](https://github.com/Skyvern-AI/skyvern/blob/695c05698eba52716521dd2b49800e88f314b660/skyvern/services/workflow_schedule_service.py#L1) implement a local scanner with deterministic scheduled-run IDs and bounded concurrency. Cloud overrides this with Temporal. The route's disabled-flag error mentions using Cloud; reading that error alone would misclassify the default local feature. Scheduling was not run during this audit.

**Retries have an explicit state model.** [`workflows.py:1700-1747`](https://github.com/Skyvern-AI/skyvern/blob/695c05698eba52716521dd2b49800e88f314b660/skyvern/schemas/workflows.py#L1700) caps retries at five and controls notification frequency. [`retry_policy.py:114-128`](https://github.com/Skyvern-AI/skyvern/blob/695c05698eba52716521dd2b49800e88f314b660/skyvern/forge/sdk/workflow/retry_policy.py#L114) excludes canceled runs. [`runRetryState.ts:17-42`](https://github.com/Skyvern-AI/skyvern/blob/695c05698eba52716521dd2b49800e88f314b660/skyvern-frontend/src/routes/workflows/workflowRun/runRetryState.ts#L17) separates a failed attempt awaiting retry from a final failed run. Agent Workspaces should adopt the clarity, while retaining stricter protection against retrying uncertain external writes.

**Recovery success and outcome validity are different.** [`self_heal.py:179-218`](https://github.com/Skyvern-AI/skyvern/blob/695c05698eba52716521dd2b49800e88f314b660/skyvern/schemas/self_heal.py#L179) tracks healed, unverified and failed outcomes, while [`self_heal_reliability_service.py:13-30`](https://github.com/Skyvern-AI/skyvern/blob/695c05698eba52716521dd2b49800e88f314b660/skyvern/services/self_heal_reliability_service.py#L13) aggregates recent runs. Our repeated-action circuit breaker is useful, but is not a diagnosis, a resume strategy or a user-accepted-output metric.

**Review is tied to the actual paused work.** [`HumanInteractionBlock:14414-14510`](https://github.com/Skyvern-AI/skyvern/blob/695c05698eba52716521dd2b49800e88f314b660/skyvern/forge/sdk/workflow/models/block.py#L14414) defines approval/rejection/timeout behavior; [`WorkflowRunHumanInteraction.tsx:26-90`](https://github.com/Skyvern-AI/skyvern/blob/695c05698eba52716521dd2b49800e88f314b660/skyvern-frontend/src/routes/workflows/workflowRun/WorkflowRunHumanInteraction.tsx#L26) guards against acting on a historical checkpoint. We should preview the exact action or artifact, bind approval to its version, and make revision invalidate old approval.

## Current Agent Workspaces gaps confirmed in code

1. [`packages/agent-loop/tools.ts:5`](<../../packages/agent-loop/tools.ts#L5>) exposes approved-origin open/observe/navigate, container-only approved upload and private report tools, but no general click, fill, select or browser download. The browser service/owner UI having low-level interaction is different from a model being allowed to use it. Wider web automation requires real broker/tool work.
2. [`packages/contracts/workflows.ts:4`](<../../packages/contracts/workflows.ts#L4>) only has text/multiline/websites/email inputs. [`packages/workflows/index.ts:99`](<../../packages/workflows/index.ts#L99>) saves objective, criteria and policy; it does not save a parameter schema, exact file-slot contract, tested procedure or output schema. Reusable brief templates are already present; do not call them an absent feature.
3. [`packages/agent-loop/tools.ts:28`](<../../packages/agent-loop/tools.ts#L28>) limits Gmail to unread headers/snippets, at most 50 per read, with no bodies/attachments/status changes. The Gmail-specific tool branch also omits code/read-file tools. Email-to-attachment-analysis, drafts and CRM updates are currently unsupported jobs.
4. [`apps/desktop/renderer/Files.tsx:47`](<../../apps/desktop/renderer/Files.tsx#L47>) and [`packages/artifacts/index.ts:343`](<../../packages/artifacts/index.ts#L343>) expose bounded plain-text/metadata previews; richer document/table/image review needs a safe preview path. Existing artifact import/export/publication should be retained.
5. [`implementation-plan.md:167`](<../../implementation-plan.md#L167>) still leaves integrated recovery, portable restore, local package and sleep/wake release gates outstanding. These are foundations of user trust, not optional polish after adding automation.
6. [`AgentRun.tsx:42`](<../../apps/desktop/renderer/AgentRun.tsx#L42>) already shows cost, tokens, steps and active time, and waiting is excluded. New work should extend this with accepted outcomes, intervention counts and repeatability, not recreate token counters.

## Positioning and commercial evidence

The [Desktop README](https://github.com/browser-use/desktop/blob/f073b7574f7927185ebbebd87556391d5cb0cfd1/README.md) presents a downloadable agent hub with provider subscription/API options. No separate Desktop commercial tariff was established here. The [Browser Use cloud pricing page](https://browser-use.com/pricing) and [homepage](https://browser-use.com/) currently market usage-based cloud agents/infrastructure; these are different products and must not be quoted as the Desktop price. Homepage benchmarks are vendor-run claims, not proof of our model's performance.

[Skyvern pricing](https://www.skyvern.com/pricing), retrieved today, lists Free, $29/month Hobby, $149/month Pro and custom Enterprise. It differentiates concurrency, credentials, team features and advanced operation support; human-in-the-loop and custom code appear as Enterprise entitlements. This does not mean the corresponding OSS source is absent or that a self-hosted installation has a hosted entitlement. The [integration page](https://www.skyvern.com/integrations) explicitly distinguishes published integrations from in-progress ones. The [use-case page](https://www.skyvern.com/use-cases) emphasizes operational portal work. Adoption counts, uptime and compliance claims were not independently verified.

Inference: there is a plausible space for a Mac-first assistant that produces checked, reviewable work while keeping agent sessions/private files separate. That is a positioning hypothesis. Neither competitor breadth, repository popularity nor our regression tests prove willingness to pay.

## Audience experiments and sequencing

Keep business/agency, developer and personal entry points, but run three distinct experiments with a shared engine:

- **Business/agency:** turn two approved data exports and a few source pages into a client-ready weekly report. Measure preparation time, checked calculations, corrections, export quality and voluntary reuse next week.
- **Developer:** inspect a small authorized test site and supplied code, return reproducible findings with evidence. Measure valid findings, false positives, reproduction effort and safe patch/test output. Do not market a full coding-agent replacement based on a source-review starter.
- **Personal:** produce an explicitly bounded mail/decision brief. Measure whether priority suggestions are useful, coverage is understood, intervention burden and actual repeat use. Do not promise full-inbox understanding from snippets.

Suggested sequence: readiness and release reliability → result quality/review → carefully scoped browser actions and connections → parameterized repeatable jobs → local schedules → learned playbooks and external triggers. A full graph editor, unrestricted connector marketplace, cookie import, silent autonomous writes, enterprise compliance positioning and broad multiuser cloud administration should wait for observed demand and proven controls.

Track opt-in, local-first measures: time to first accepted deliverable; accepted useful results / started tasks; owner interventions and minutes per job; corrections and false completion; cost per accepted result; week-2 and week-4 workflow reuse. Proposed pilot targets are decision rules, not current performance. Interview users who abandon setup or reject results, and investigate failures before adding breadth.
