## C07 owner-reviewed repository snapshot pilot

The selected-source manifest alone did not fulfill the repository snapshot proposal. `packages/repository-snapshot` now previews a native owner-selected folder, caches exact immutable JSON bytes for review, then captures privately to the selected active agent and publishes a project-bound shared artifact only after explicit capture. Schema24 receipts recover the same private/shared versions across committed-operation interruptions and service restart; TTL fences uncommitted previews. Concurrent reordered command properties share one capture. No source host paths are returned or saved. Identity excludes clock/preview nonce.

Pilot limits:16files,8KiB/file,32KiBsourcebytes,64KiBwholeJSON,256scannedentries,depth8,64exclusionlabels. Source paths/text are inert evidence. Pinned Python directory descriptors and `O_NOFOLLOW` prevent child symlink redirects; the selected root descriptor must match its original dev/inode. Secret names/content, binary, symlink, oversized and limited entries are excluded before model retrieval. Detection is heuristic and omitted/excluded files are not inspected. Python `/usr/bin/python3` stdlib is required. Git metadata is read through pinned descriptors with no Git/config/hooks/network execution: bounded verified loose objects and indexv2/v3. Unsupported packed objects/worktrees/metadata remain unknown. Dirty compares captured Git blob bytes against the observed commit; this is not an atomic repository snapshot.
