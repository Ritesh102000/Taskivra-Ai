# Phase 7 implementation status

Status date: 2026-09-30. Application version: 0.7.0.

This records seven bounded priority slices implemented on the existing Mac application. It does not replace `architecture.md`, `design.md`, or `implementation-plan.md`, and it does not mark all 24 market-audit ideas complete. The original planning baseline, confirmed choices (Mac first, cloud APIs first, isolated code containers), and private-agent boundaries remain authoritative.

## Seven priority slices

| Priority slice | Implemented behavior | Material boundary |
| --- | --- | --- |
| 1. Local release, recovery and task readiness — F01/F02 | Explicit Mac package inventory; native credential setup; verified backup into a new destination; separately restored, paused work; capability-specific task doctor; preserved in-session workflow drafts; safe links to setup. Gmail readiness checks both the selected account and project approval. Pinned PDF/XLSX inputs require the isolated document image and exact parser packages. | Packaging is for local testing with ad-hoc signing. Developer ID signing, notarization, updates and clean-machine provisioning remain external release gates. A configured key is not labelled a tested model connection. Readiness does not spend money, open websites, or read mail/documents. The existing agent-requested login flow remains available; readiness is not a blanket block on all custom tasks. |
| 2. Usable results and ordinary inputs — F03/F04/F05 | Safe Markdown/CSV previews; exact-version result inspection and acceptance; source/evidence receipts with durable retrieval; bounded request-changes tasks preserving the original result; inert source-code file previews; bounded PDF/XLSX extraction through isolated code execution. | Integrity, observed evidence, owner acceptance and semantic correctness are distinct. There is no automatic proof that a report is factually correct. PDF extraction is text-based, not OCR; encrypted/active/unsupported content is refused. XLSX formula caches and typed values are described explicitly; macros are never executed. DOCX generation and a general polished-report export suite remain future work. |
| 3. Parameterized reusable jobs — F06 | Six starter workflows with content-addressed procedure versions, named fields, examples and output contracts; optional parameterized saving; a two-CSV comparison with explicit current/comparison slots and preflight format/content checks. Exact assigned versions are checked again at task admission. | Reuse does not clone credentials, file assignments or previous account grants. Manual-brief saving remains supported. | 4. Project spaces and reviewed knowledge — F07 | Immutable agent/project membership after work exists; project-scoped tasks, publications and collaboration; versioned owner-reviewed briefs and selected published knowledge; separate exact Gmail and Google Drive account approvals. | This is local project separation, not multi-user cloud tenancy, enterprise role administration or automatic memory ingestion. Knowledge still needs explicit task input grants. Restored project data does not recreate credential authority. |
| 5. Selected Google inputs and deeper mail review — F09/F10 | Independent Drive connection; exact selected Drive/Doc/Sheets snapshots with source version/hash receipts; profile-only Verify account after restart; opt-in Gmail search, selected plain-text threads and safe selected attachments; owner and agent authorization checks before reads and again at local import commit. | Requires an owner-imported Desktop OAuth client and external Google API/consent setup. Google grants broad `drive.readonly` provider access; application code limits this import feature to the selected resource. Existing unread-snippet tasks remain unchanged. Mail search is capped at 20 messages/page and five pages; thread/body/MIME/attachment limits and omissions are explicit. No mailbox/document writes. |
| 6. Local recurring jobs — F11 | Repeat accepted, versioned read-only work at a reviewed time/day schedule; timezone and expiration; per-run and monthly spend caps; durable occurrence identity; no overlapping automatic dispatch; visible skipped/blocked runs; pause controls. | The Mac/app must be available. Missed work is skipped rather than released as a burst. The slice does not silently refresh stale input files or provide cloud always-on execution. Current acceptance, setup and account grants are rechecked; uncertain paid usage retains its reservation. |
| 7. Owner-reviewed browser actions — F13 | Explicit action-enabled task policy; fresh-target click/fill/select proposals; one owner decision bound to the exact target, payload, page revision, browser generation, project brief revision and stated account; single-use dispatch; post-action observations and saved unknown outcomes; model tools for multiple tabs and private managed-download imports. | A browser action can submit or autosave. Approval is for one exact effect, never reusable website authority. Stale pages/handoffs/corrections invalidate proposals. Uncertain effects stop for review without automatic replay. Native Chrome managed uploads/downloads and broad unattended website automation remain outside the current capability promise. |

The requested breadth still serves business/agency, developer and personal use cases, but these are capability and usability hypotheses. No interviews, activation/retention study, willingness-to-pay experiment, external sales outreach or product-market-fit claim is implied by implementation.

## Evidence and verification

The focused suites exercise actual boundaries, rather than counting UI controls as completed work:

- Readiness/workflow fixtures cover optional capability isolation, native Chrome without Docker, configured-versus-tested state, missing/mismatched/revoked project accounts, pinned document parser requirements, CSV slot validation, immutable definitions, restart, and detailed-mail grant opt-in. The latest dedicated run passed 24 tests.
- Google/Gmail service fixtures cover separate read-only OAuth scope, synthetic PKCE callback, exact account checks, provider response bounds, selected ranges, source-version changes, cursor/selection expiry, body/attachment handling, and the 22,000-byte agent receipt limit. The dedicated new service run passed 22 tests; the existing 12 Gmail OAuth/unread regression tests passed after the shared transport change.
- Eight connector/controller/import integration tests passed through the real managed artifact service. A fake provider's chosen content and source receipt were imported and previewed as exact private versions. Cross-project targets, revoked account approval during download and after staging, cancelled task state, and early cleanup failures were refused. Connector bytes are cleared on both success and failure.
- Results, evidence, file preview, project boundaries, routines, browser actions, recovery and package-inventory suites are present under `tests/phase7`. The integrated release run below verifies the final combination, with explicit skips and live-service limits.
- Type checking passed during this slice. The separate native Drive Keychain helper compiled without reading or writing credentials.

The fixture OAuth callback runs locally with synthetic tokens and mocked Google responses. These tests do not prove a live Google account connection, live mailbox quality, live Drive access, or paid model quality. No real OAuth account read/write or paid model request was performed by the connector/readiness implementation work. Runtime-specific evidence must identify its exact image and tested boundary; a successful container fixture is not a clean-machine deployment result.

## Integrated release verification

Final source passed type checking and the production build. The same JavaScript suite ran under Node 26.7.0 and Electron 44.3.0: **568 tests total, 550 passed, 0 failed, 18 skipped in each runtime**. The separate Phase 0 local gate also passed. Full local logs and a compact summary are retained in `docs/phase7/evidence/release-checks.json`, `node-tests.log`, `electron-tests.log`, and `phase0-tests.log`.

The 18 opt-in skips include paid OpenAI requests, Keychain mutation, real Chrome, and heavyweight Docker gates. Separate real container evidence was collected for reviewed browser click/fill/select and page-mutation rejection (`tests/phase3/evidence/worker-docker.json`), plus PDF/XLSX extraction using both the installed document image and the portable pinned-base image (`document-extraction.json`, `document-extraction-portable.json`). These do not imply all skipped gates were rerun.

The local Apple Silicon package was created at `dist/packages/Agent-Workspaces-0.7.0-arm64-local/Agent Workspaces.app`. All 30 allowlisted packaged resources matched their recorded hashes; local ad-hoc signature verification passed. The packaged app opened both an isolated UI fixture and the existing owner workspace. It remains **not notarized or Developer ID signed**.

Native desktop checks covered report rendering and exact-version acceptance, a separate paused revision task, accepted-job schedule eligibility, project/account panels, connection/recovery controls, and CSV workflow readiness and assignment controls. Synthetic tasks made zero model calls and enabled no routines. Final Routines layout and production navigation rendered correctly. This is recorded in `desktop-ui.json`.

Before opening the updated app, the full existing data folder was preserved in `~/Desktop/Agent Workspaces Backups/before-0.7.0-20260930-140420`. A separate migration rehearsal and the actual startup both moved schema 8 to 13 with intact database/FK checks and unchanged counts for existing agents, tasks, messages, artifacts, requests, runs, browser sessions and model calls. The app is open on the original workspace. No new paid model calls or Google account reads were performed. See `production-migration.json` and `production-upgrade.json`.

The final lifecycle review also tested delayed owner-code cleanup and stopping runtimes before waiting on workers, and fenced key changes against pending replans. Sleep requests received during a native picker remain queued while model/runtime work stops; backup and sleep leave schedules disabled for explicit review. Native OS sleep itself was not induced as an end-to-end test.

## Remaining work and decisions

- Choose distribution/signing and fresh-machine runtime provisioning before describing this as a public Mac release.
- Provide external Google OAuth project/client configuration and required verification for an application-managed connection. The supported owner-client path is explicit in Settings.
- Validate three complete real jobs with appropriate data, account permissions and an explicitly chosen model budget: a supplied-CSV comparison, a bounded mail brief, and a sourced web/developer review. Measure owner acceptance and corrections separately from technical execution success.
- F08 web search-provider discovery, unattended cloud scheduling, general DOCX/report publishing, native-browser managed transfers, marketplace expansion and other unselected audit ideas remain future work. They should follow evidence from repeated useful tasks.
